# เปรียบเทียบ Local AI ด้วย Docker Compose, Ollama และ Continue

โปรเจกต์ทดลองรับคำถามเป็นข้อความ แล้วส่งคำถามเดียวกันให้ **Qwen2.5-Coder 1.5B** และ **Llama 3.2 3B** ผ่าน Ollama เพื่อเปรียบเทียบคำตอบ เวลารอ และความเหมาะสมกับงาน พร้อมตัวอย่างการเชื่อมโมเดลกับ Continue ใน VS Code

## สถานะของงาน

- มีโปรแกรม Python รับข้อความและบันทึกคำตอบจากทั้งสองโมเดล
- มีผลทดลองเดิม 4 คำถาม และรอบตรวจระบบหลังใช้ Compose อีก 1 ชุด รวม 10 คำตอบ ใน `results/`
- มีตัวอย่างการตั้งค่า Continue สำหรับสองโมเดล โหมด Chat
- แนบภาพ Compose, ผล Python และ Continue หลังเปลี่ยนระบบแล้ว ไม่มีเวลาที่วัดจาก Continue จึงไม่รวมคำตอบ Continue ในตารางเวลา
- `prompt.txt` เป็นโจทย์สำหรับต่อยอดสร้างเว็บ To-do List ยังไม่มีไฟล์เว็บหรือผลทดสอบเว็บในโปรเจกต์ชุดนี้
- โปรเจกต์นี้ยังไม่ใช้ CrewAI, OpenClaw หรือ Chatbox

## วัตถุประสงค์

1. เรียนรู้การรันโมเดลในเครื่องผ่าน Ollama บน Docker
2. เปรียบเทียบสองโมเดลด้วยคำถามและค่าตั้งเดียวกัน
3. ประเมินความถูกต้อง ความชัดเจน การทำตามคำสั่ง และเวลารอ
4. เชื่อมโมเดลกับ Continue เพื่อใช้งานใน VS Code

## ติดตั้งและเริ่มใช้งาน

ติดตั้ง [Docker Desktop](https://www.docker.com/products/docker-desktop/), [Python 3](https://www.python.org/downloads/) และ [VS Code](https://code.visualstudio.com/) แล้วเปิด Docker Desktop ให้พร้อม

เปิด Terminal ในโฟลเดอร์โปรเจกต์ ตรวจเครื่องมือ:

```bash
python3 --version
docker --version
```

### 1. เปิดระบบด้วย Compose

รันคำสั่งจากโฟลเดอร์ที่มี `compose.yaml` โดยเปิด Docker Desktop ก่อน

**สำหรับเครื่องใหม่:** สร้างพื้นที่เก็บโมเดลก่อน เพราะไฟล์นี้ใช้ `external: true`:

```bash
docker volume create ollama
```

**สำหรับเครื่องที่ย้ายมาใช้ Compose สำเร็จแล้ว:** ใช้ volume เดิมได้ ไม่ต้องย้ายหรือเปลี่ยนชื่อคอนเทนเนอร์ซ้ำ

```bash
docker compose version
docker compose config
docker compose up -d
docker compose ps
```

ควรเห็นบริการ `ollama` สถานะ Up พอร์ต `127.0.0.1:11434` ใช้จากเครื่องเดียวกัน Python และ Continue ใช้ที่อยู่เดิม `http://localhost:11434`

หากยังมีคอนเทนเนอร์ `ollama` จากคำสั่ง `docker run` เดิม ให้ดู [วิธีย้ายระบบ](#ย้ายจากคอนเทนเนอร์เดิมครั้งเดียว) ก่อนสั่งเปิด Compose

### 2. ตรวจและดาวน์โหลดโมเดล

```bash
docker compose exec ollama ollama list
```

หากยังไม่มีโมเดล ให้ดาวน์โหลด (ใช้อินเทอร์เน็ต):

```bash
docker compose exec ollama ollama pull qwen2.5-coder:1.5b
docker compose exec ollama ollama pull llama3.2:3b
```

โมเดลเก็บใน Docker volume `ollama` ไม่ได้รวมใน GitHub เครื่องใหม่ต้องดาวน์โหลดเอง ส่วนเครื่องที่มีทั้งสองโมเดลแล้วไม่ต้องโหลดซ้ำ

### 3. รันโปรแกรม

```bash
python3 chat_input.py
```

พิมพ์คำถามแล้วกด Enter โปรแกรมจะเรียก Qwen ก่อน แล้วเรียก Llama จากนั้นบันทึกผลลง `results/` อัตโนมัติ

- `/examples` แสดงคำถามตัวอย่าง ไม่ได้รันทดสอบทุกข้ออัตโนมัติ
- `exit` ออกจากโปรแกรม
- แต่ละคำถามเริ่มใหม่ ไม่มีประวัติสนทนาข้ามคำถาม
- โปรแกรมรับข้อความทีละบรรทัด และไม่ได้อ่าน `prompt.txt` อัตโนมัติ

## วิธีทดลองและความหมายของเวลา

ใช้ system prompt เดียวกัน: “ตอบคำถามเป็นภาษาไทยอย่างชัดเจน กระชับ และถูกต้อง หากไม่ทราบให้บอกว่าไม่ทราบ”

| ค่าตั้ง | ค่า |
|---|---|
| `temperature` | 0 |
| `seed` | 42 |
| `num_ctx` | 4096 |
| `num_predict` | 768 |
| `stream` | false |
| `keep_alive` | 0 |

โปรแกรมไม่มีขั้น warm-up และขอให้ unload โมเดลหลังตอบแต่ละครั้ง แต่ไม่ได้บังคับ unload ก่อนเริ่มคำถามแรก หากโมเดลโหลดอยู่ก่อน สภาพเริ่มต้นอาจต่างกัน

- `elapsed_seconds`: เวลารอจากก่อนส่งคำขอจนรับและอ่านคำตอบเสร็จ รวมเวลาโหลดโมเดลถ้ามี
- `load_seconds`: เวลาโหลดโมเดลที่ Ollama รายงาน
- `total_seconds_ollama`: เวลารวมที่ Ollama รายงาน
- `output_tokens`: จำนวนโทเคนคำตอบ ไม่ใช่จำนวนคำภาษาไทย
- `truncated`: คำตอบสิ้นสุดเพราะถึงขีดจำกัดความยาวหรือไม่

ผลทั้ง 10 คำตอบที่แนบมี `done_reason: stop` และ `truncated: false`

### ตรวจ Continue หลังเปลี่ยนระบบ

- Llama ใน Chat ตอบ “The answer is 20.” ตรงกับคำถาม
- Qwen ใน Chat แสดงคำตอบ 20 ในกรอบโค้ด `main.py` พร้อมข้อความส่วนเกิน รูปแบบไม่เหมาะกับคำถามคำนวณทั่วไป และ `10 + 10 = 20` ไม่ใช่คำสั่ง Python ที่ถูกต้อง
- ไม่ได้กดสร้างไฟล์จากกรอบคำตอบ และภาพเพียงอย่างเดียวไม่ใช่หลักฐานว่ามีการสร้างไฟล์
- ไม่มีการจับเวลาใน Continue รอบนี้ ตัวเลขใน Terminal เป็นผล Python

### ข้อสรุปสำหรับเลือกโมเดล

จากข้อมูลชุดเล็กนี้ **เสนอเลือก Llama 3.2 3B สำหรับงานอธิบายความรู้พื้นฐานภาษาไทย** เพราะคำตอบ CPU/RAM ชัดกว่าคำตอบ Qwen ที่มีข้อผิดพลาด แม้ Llama ยังมีปัญหาพูดซ้ำในโจทย์ HTML/CSS/JavaScript ส่วน Qwen มีเวลารอน้อยกว่าใน 3 จาก 4 คำถาม และตอบโจทย์คำนวณได้ถูกต้อง

ข้อเสนอนี้ไม่ใช่ข้อพิสูจน์ว่า Llama ดีกว่าทุกงาน และยังไม่มีผลสร้างเว็บเพื่อสรุปความสามารถด้านเขียนโค้ด ผู้จัดทำควรตรวจและยืนยันเหตุผลการเลือกก่อนนำเสนอ

## เชื่อมกับ Continue ใน VS Code

1. ติดตั้งส่วนเสริม **Continue** ผู้เผยแพร่ Continue (`Continue.continue`)
2. เปิด Docker และคอนเทนเนอร์ Ollama
3. เปิดการตั้งค่า local config ของ Continue (`~/.continue/config.yaml` บน Mac)
4. สำรองค่าที่มีอยู่ก่อน หากเคยตั้งค่าใช้งานอื่นไว้
5. คัดลอกเนื้อหาจาก `continue-config.example.yaml` ไปใช้ในไฟล์ตั้งค่าจริง แล้วบันทึก
6. เปิดแชทใหม่ เลือกโหมด Chat และเลือกโมเดลที่ต้องการ

ไฟล์ `continue-config.example.yaml` ในโปรเจกต์เป็นตัวอย่าง ไม่ได้มีผลกับ Continue อัตโนมัติ บทบาท `chat` ในไฟล์นี้ไม่ได้รับรองว่ารองรับการเรียกเครื่องมือในโหมด Agent

ตัวอย่างงานง่ายสำหรับสาธิต:

```text
สรุปข้อความต่อไปนี้เป็นรายการสิ่งที่ต้องทำ 3 ข้อ โดยไม่เพิ่มข้อมูลใหม่:
วันนี้ฉันต้องอ่านบทเรียนเรื่อง Docker จากนั้นทดลองใช้ AI ผ่าน Ollama และบันทึกผลการทดลองเพื่อนำไปนำเสนออาจารย์
```

หากวัดเวลาใน Continue ให้จับเวลาตั้งแต่กดส่งจนตอบเสร็จ พร้อมบันทึกโมเดล โหมด และว่าได้ warm-up หรือไม่ แยกตารางนี้จากผล Python เพราะเส้นทางเรียกใช้และค่าตั้งอาจต่างกัน

## ข้อจำกัดและการพัฒนาต่อ

- มีคำถามไม่ซ้ำเพียง 4 ข้อ และทดสอบ 10+10 อีกครั้งหลังเปลี่ยนระบบ จึงยังไม่ใช่ผลสถิติที่เชื่อถือได้ในวงกว้าง
- โมเดลมีขนาดต่างกัน และความยาวคำตอบต่างกัน เวลารอจึงไม่ใช่การเปรียบเทียบความเร็วสร้างโทเคนล้วน
- ลำดับการรันคงที่ Qwen ก่อน Llama; ภาระงานและหน่วยความจำเครื่องอาจมีผล
- ไม่มีผลทดสอบข้ามเครื่องผ่าน Wi-Fi การใช้ `localhost` คือการเรียกบนเครื่องเดียวกัน
- มีภาพ Continue แต่ยังไม่มีคลิปหรือไฟล์เว็บที่ทดสอบสำเร็จในชุดนี้
- การพัฒนาต่อ: ทดสอบซ้ำอย่างน้อย 3 รอบต่อคำถาม แยกผลแบบโมเดลโหลดอยู่กับแบบต้องโหลด และบันทึกเวอร์ชัน/สเปกให้ครบ
- หากต่อยอดโจทย์เว็บใน `prompt.txt` ให้เก็บโค้ดของแต่ละโมเดลแยกกัน แล้วตรวจเพิ่มงาน ลบงาน ติ๊กเสร็จ ป้องกันงานว่าง และรีเฟรชแล้วยังมีข้อมูล

## แก้ปัญหาเบื้องต้น

| อาการ | สิ่งที่ตรวจ |

### ย้ายจากคอนเทนเนอร์เดิมครั้งเดียว

ขั้นตอนนี้สำหรับคนที่เคยสร้าง `ollama` ด้วย `docker run` เท่านั้น ผู้จัดทำทำเสร็จแล้ว ไม่ต้องทำซ้ำ

ตรวจพื้นที่เก็บเดิม:

```bash
docker inspect ollama --format '{{range .Mounts}}{{println .Type .Name .Destination}}{{end}}'
```

ต้องพบ `volume ollama /root/.ollama` หากต่างออกไปให้ปรับการอ้างอิง volume ให้ตรงก่อนดำเนินการ

เมื่อไม่มีคำขอ AI กำลังทำงาน ให้รันทีละคำสั่ง และหยุดหากมี error:

```bash
docker stop ollama
docker rename ollama ollama-backup
docker compose up -d
docker compose ps
docker compose exec ollama ollama list
```

`ollama-backup` เก็บคอนเทนเนอร์เดิมในสถานะหยุด ไม่ใช่สำเนาข้อมูลโมเดลแยกต่างหาก เพราะใช้ volume เดียวกัน อย่าเปิดพร้อมตัวใหม่

หากต้องย้อนกลับหลังสร้างคอนเทนเนอร์ Compose แล้ว ให้หยุดบริการและนำคอนเทนเนอร์ Compose ออกก่อน:

```bash
docker compose down
docker rename ollama-backup ollama
docker start ollama
```

volume ที่กำหนดเป็น external แยกการจัดการจาก Compose ไม่ต้องลบ volume เพื่อย้ายระบบ
