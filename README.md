# เปรียบเทียบ Local AI และสาธิต Agent ด้วย Docker Compose และ Ollama

โปรเจกต์ทดลองรับคำถามเป็นข้อความ แล้วส่งคำถามเดียวกันให้ **Qwen2.5-Coder 1.5B** และ **Llama 3.2 3B** ผ่าน Ollama เพื่อเปรียบเทียบคำตอบและเวลารอ พร้อมทดลอง Agent ที่เลือกใช้เครื่องมืออ่านและเขียนไฟล์ โดยรัน Ollama และโปรแกรมหลักใน Docker ตามขอบเขตที่ผู้จัดทำได้รับจากอาจารย์

## สถานะของงาน

- มีโปรแกรมเปรียบเทียบสองโมเดล พร้อมผลทดลองที่อ่านได้ **12 รอบ รวม 24 คำตอบ จากคำถามไม่ซ้ำ 8 ข้อความ** ใน `results/`
- มี Agent ใช้ Qwen แปลงบันทึกเป็น checklist ผ่าน Docker Compose โดยรอบล่าสุดที่แนบหลักฐานคือ **19 ตุลาคม 2026 เวลา 19:22:57** ผ่านเงื่อนไขตรวจของโปรแกรม **7/7 ข้อ**
- มี `compose.yaml` และ Dockerfile สำหรับกำหนดบริการ สร้างโปรแกรม และเก็บผลกลับลงโฟลเดอร์บนเครื่อง
- มีข้อมูลเวอร์ชันระบบ รายชื่อโมเดล และผลตรวจ Docker/MCP ใน `evidence/`
- มีตัวอย่าง config และภาพ Continue โหมด Chat ส่วนการเรียกเครื่องมือผ่าน Continue Agent UI ยังไม่ได้ยืนยัน

## วัตถุประสงค์

1. เรียนรู้การรันโมเดล AI บนเครื่องผ่าน Ollama ใน Docker
2. เปรียบเทียบสองโมเดลด้วยคำถามและค่าตั้งเดียวกัน
3. วิเคราะห์ความถูกต้อง ความชัดเจน การทำตามคำสั่ง และเวลารอ
4. ทดลองให้โมเดลเลือกใช้เครื่องมือเพื่ออ่าน สร้าง และตรวจไฟล์
5. จัดเก็บโค้ด วิธีใช้งาน และผลทดลองเพื่อใช้ตรวจสอบและนำเสนอ

## สถาปัตยกรรมระบบ

```text
Terminal บนเครื่อง
       ↓ สั่งงานผ่าน Docker Compose
โปรแกรม Python ใน Docker (compare หรือ Agent)
       ↓ ส่งคำขอไปยัง http://ollama:11434
Ollama ใน Docker → โมเดล Qwen หรือ Llama
       ↓ ส่งคำตอบกลับให้ Python
แสดงผลใน Terminal และบันทึกไฟล์ลงโฟลเดอร์บนเครื่อง
```

- โมเดลเก็บใน **Docker volume** ชื่อ `ollama` เพื่อใช้งานต่อเมื่อเปิดระบบใหม่
- ผลทดลองและไฟล์งานใช้ **bind mount** ซึ่งเชื่อมโฟลเดอร์ในโปรเจกต์เข้ากับ container จึงเปิดผลจาก VS Code ได้หลังโปรแกรมจบงาน
- Continue บนเครื่องเชื่อมไปยัง `localhost:11434` ส่วนโปรแกรมภายใน Docker เชื่อมไปยัง `ollama:11434`

การกำหนดบริการและวิธีสร้างโปรแกรมไว้ในไฟล์เป็นส่วนของ **Infrastructure as Code (IaC)** ดู [แผนภาพและรายละเอียดสถาปัตยกรรม](docs/ARCHITECTURE.md)

## ติดตั้งและเริ่มใช้งาน

ติดตั้งและเปิด [Docker Desktop](https://www.docker.com/products/docker-desktop/) แล้วเปิดโปรเจกต์ใน VS Code โปรแกรมหลักใช้ Python ที่อยู่ใน Docker image

เปิด Terminal ในโฟลเดอร์ที่มี `compose.yaml` แล้วตรวจเครื่องมือ:

```bash
docker --version
docker compose version
docker compose config
```

### 1. เปิด Ollama ด้วย Compose

เครื่องที่ยังไม่มี volume ให้สร้างพื้นที่เก็บโมเดลก่อน เพราะ Compose ใช้ `external: true` คำสั่งนี้ใช้กับ volume ที่มีอยู่แล้วได้:

```bash
docker volume create ollama
docker compose up -d ollama
docker compose ps
```

ควรเห็นบริการ `ollama` ทำงาน หากมี container `ollama` จาก `docker run` เดิมใช้ชื่อหรือพอร์ตเดียวกัน ให้ดู [วิธีย้ายระบบ](#ย้ายจากคอนเทนเนอร์เดิมครั้งเดียว) ก่อนเปิด Compose

### 2. ตรวจและดาวน์โหลดโมเดล

```bash
docker compose exec ollama ollama list
```

หากยังไม่มีโมเดล ให้ดาวน์โหลดขณะมีอินเทอร์เน็ต:

```bash
docker compose exec ollama ollama pull qwen2.5-coder:1.5b
docker compose exec ollama ollama pull llama3.2:3b
```

โมเดลเก็บใน volume `ollama` และไม่ได้รวมอยู่ใน GitHub เครื่องใหม่ต้องเตรียมโมเดลก่อนใช้งาน

### 3. สร้างโปรแกรมใน Docker

เตรียม image ขณะมีอินเทอร์เน็ต และทำซ้ำเมื่อแก้โค้ดโปรแกรม:

```bash
docker compose --profile tools build compare agent
```

### 4. รันโปรแกรมเปรียบเทียบโมเดล

หลังเปิด Ollama และเตรียม image แล้ว ให้รัน:

```bash
docker compose --profile tools run --rm --no-deps --pull never compare
```

พิมพ์คำถามแล้วกด Enter เช่น:

```text
HTML, CSS และ JavaScript ทำหน้าที่ต่างกันอย่างไร ตอบเป็น 3 ข้อ
```

โปรแกรมเรียก **Qwen ก่อน แล้วจึงเรียก Llama** แสดงคำตอบและเวลา พร้อมบันทึกลง `results/` หลังแต่ละโมเดล

- `/examples` แสดงคำถามตัวอย่างสำหรับคัดลอกมาทดลอง
- `exit` ออกจากโปรแกรม
- แต่ละคำถามเริ่มใหม่ ไม่มีประวัติสนทนาข้ามคำถาม
- โปรแกรมรับข้อความทีละบรรทัด และไม่ได้อ่าน `prompt.txt` อัตโนมัติ

### 5. รันโปรแกรม Agent

หลังออกจาก compare ให้รัน:

```bash
docker compose --profile tools run --rm --no-deps --pull never agent --demo --runtime docker
```

ค่าเริ่มต้นใช้ Qwen2.5-Coder 1.5B และให้โมเดลเลือกเครื่องมือด้วย JSON ซึ่งเป็นรูปแบบข้อมูลที่ Python อ่านเพื่อเรียกเครื่องมือต่อได้ รายละเอียดโจทย์และผลอยู่ในหัวข้อ “การทดลอง Local Agent”

คำสั่งรันทั้งสองใช้ image ที่เตรียมไว้โดยไม่สั่ง build หรือ pull image จึงใช้งานแบบ offline ได้เมื่อมี image และโมเดลครบ และเปิด Ollama แล้ว หลักฐานที่แนบยังไม่ได้บันทึกสถานะการตัดอินเทอร์เน็ตจริง

## วิธีทดลองและความหมายของเวลา

Compare ใช้ system prompt เดียวกัน: “ตอบคำถามเป็นภาษาไทยอย่างชัดเจน กระชับ และถูกต้อง หากไม่ทราบให้บอกว่าไม่ทราบ”

| ค่าตั้ง | ค่า |
|---|---|
| `temperature` | 0 |
| `seed` | 42 |
| `num_ctx` | 4096 |
| `num_predict` | 768 |
| `stream` | false |
| `keep_alive` | 0 |

โปรแกรมไม่มีขั้น warm-up และขอ unload โมเดลหลังตอบ แต่ไม่ได้บังคับ unload ก่อนคำถามแรก หากมีโมเดลโหลดอยู่ก่อน สภาพเริ่มต้นอาจต่างกัน

- `elapsed_seconds`: เวลารอจากก่อนส่งคำขอจนรับคำตอบเสร็จ รวมเวลาโหลดโมเดลเมื่อมี
- `load_seconds`: เวลาโหลดโมเดลที่ Ollama รายงาน
- `total_seconds_ollama`: เวลารวมที่ Ollama รายงาน
- `output_tokens`: จำนวนโทเคนคำตอบ ไม่ใช่จำนวนคำภาษาไทย
- `truncated=true`: คำตอบถึงขีดจำกัดความยาว อาจยังตอบไม่จบ

การประเมินคุณภาพใช้การอ่านคำตอบเพื่อตรวจความถูกต้อง ความชัดเจน และการทำตามคำสั่ง แยกจากการเปรียบเทียบเวลา

| คำถาม | Qwen | Llama | การประเมินจากคำตอบ |
|---|---:|---:|---|
| [10 + 10](results/20261018_143617_008885.txt) | 1.640 | 3.528 | ทั้งสองตอบ 20 ถูกต้อง |

เวลาในตารางเป็นเวลารอรวมการโหลดโมเดลเมื่อมี จึงไม่ใช่ความเร็วสร้างคำตอบล้วน รอบสาธิตใหม่อาจได้เวลาและคำตอบต่างจากตาราง

คำตอบที่จบตามปกติยังต้องตรวจเนื้อหา ผลทั้งหมดเก็บตามที่ได้จริงโดยไม่แก้คำตอบหรือเวลาต้นฉบับ

## การทดลอง Local Agent

Agent ในโครงงานนี้คือการให้โมเดลเลือกใช้เครื่องมือเพื่อทำงานต่อเนื่อง โดย Python เป็นผู้เรียกเครื่องมือและส่งผลกลับให้โมเดลตัดสินใจขั้นถัดไป เครื่องมือมี 3 อย่าง: ดูรายชื่อไฟล์ อ่านไฟล์ และเขียนไฟล์ข้อความ

### โจทย์ทดลอง

ให้ Agent อ่าน `notes.txt` แล้วสร้าง `checklist.md` โดยเก็บงานเดิมให้ครบตามลำดับ จากนั้นเปิดไฟล์ที่สร้างมาตรวจ

| ต้นฉบับที่ Python เตรียมเมื่อใช้ `--demo` | ผลที่ Agent ต้องสร้าง |
|---|---|
| `Study Docker.` | `- [ ] Study Docker.` |
| `Run local AI with Ollama.` | `- [ ] Run local AI with Ollama.` |
| `Save experiment results.` | `- [ ] Save experiment results.` |

งานที่สำเร็จคือการแปลงบันทึกให้มีช่องติ๊ก `[ ]` ส่วนข้อความทั้งสามรายการเป็นข้อมูลในไฟล์ โจทย์นี้เลือกเพื่อทดสอบการใช้เครื่องมือและตรวจผลได้ชัดเจน เกณฑ์ใน PDF กล่าวถึง Local Agentic แต่ไม่ได้กำหนดให้ทำ checklist โดยเฉพาะ

### ขั้นตอนการทำงาน

1. โมเดลเลือก `read_file` → Python เปิด `notes.txt` และส่งเนื้อหาให้โมเดล
2. โมเดลเลือก `write_file` → Python บันทึกเนื้อหาที่โมเดลส่งมาเป็น `checklist.md`
3. โมเดลเลือก `read_file` → Python อ่านไฟล์ที่สร้างกลับให้โมเดลตรวจ ก่อนแจ้งจบงาน

ลำดับนี้เป็นตัวอย่างรอบที่ผ่าน บางรอบอาจใช้เครื่องมือเพิ่มหรือทำไม่ครบ Python มีตัวตรวจแยกอีกชั้นหนึ่ง ดูการใช้เครื่องมือ การเขียน–อ่านผลกลับ ลำดับอ่านต้นฉบับ การรักษาต้นฉบับ และความครบถ้วนของงาน รวม **7 เงื่อนไข** ผล `passed` จึงมาจากตัวตรวจของโปรแกรม

**7/7 เป็นผลตรวจเดโมของโปรแกรม แยกจากคะแนนตามเกณฑ์ของอาจารย์** ตัวอย่างไฟล์จริง: [ต้นฉบับ](evidence/demo-success/notes.txt) และ [checklist ที่สร้าง](evidence/demo-success/checklist.md)

### ผลตรวจ Agent ใหม่

รอบล่าสุดที่มีไฟล์หลักฐานในชุดนี้คือ **19 ตุลาคม 2026 เวลา 19:22:57 (เวลาไทย)** รันผ่าน Docker Compose ใช้ Qwen ผ่านรูปแบบคำสั่ง JSON โดยเชื่อมต่อ `http://ollama:11434` ได้ `passed / finished` ผ่าน **7/7 เงื่อนไข** ใช้เวลาวงรอบ Agent **10.783 วินาที** ไม่รวมเวลา build image

หลักฐาน: [บันทึกแบบอ่านง่าย](agent_results/20261019_192257_558909.txt), [ข้อมูล JSON](agent_results/20261019_192257_558909.json) และ [ข้อมูลที่มาของสำเนาไฟล์](evidence/demo-success/provenance.json)

มีบันทึก Agent รวม 10 รอบ ผ่าน 4 รอบ อีก 6 รอบทำไม่ครบ รวมถึงการทดลองรูปแบบเรียกเครื่องมืออื่นและผล Llama ดู [ตารางทุกรอบและสาเหตุ](evidence/AGENT-RUNS.md) บางรอบมีการปรับโค้ดและคำสั่งระหว่างพัฒนา จึงไม่ใช้ชุดนี้จัดอันดับความเร็วโมเดล

### ตำแหน่งผลหลังรัน

- `agent_workspace/<รหัสรอบ>/notes.txt` — ต้นฉบับ
- `agent_workspace/<รหัสรอบ>/checklist.md` — ผลงาน
- `agent_results/<รหัสรอบ>.txt` และ `.json` — ขั้นตอน เครื่องมือ และผลตรวจ

รหัสรอบแสดงใน Terminal หากพาธขึ้นต้น `/app/` นั่นคือพาธใน container ให้เปิดโฟลเดอร์ชื่อเดียวกันในโปรเจกต์บนเครื่อง

## ข้อสรุป

จาก 4 คำถามชุดแรก Qwen ใช้เวลารอน้อยกว่า 3 ข้อ และทั้งสองตอบโจทย์คำนวณง่ายได้ถูก ส่วน Llama อธิบาย CPU/RAM ชัดกว่า Qwen ในตัวอย่างนี้ ผลเพิ่มเติมแสดงว่าทั้งสองยังตอบผิด พูดซ้ำ หรือทำตามคำสั่งไม่ครบได้ จึงต้องพิจารณาคุณภาพร่วมกับเวลา

เลือก Qwen แบบ JSON เป็นค่าเริ่มต้นสำหรับเดโม Agent เพราะมีผลอ่าน–สร้าง–ตรวจไฟล์ผ่านตามหลักฐานที่แนบ การผ่านเดโมครั้งหนึ่งไม่รับรองว่าจะผ่านทุกครั้ง และผลชุดเล็กนี้ยังไม่เพียงพอจะสรุปว่าโมเดลใดดีกว่าทุกงาน

## การเชื่อมต่อ Continue และ MCP

Continue เป็นอีกช่องทางส่งคำถามจาก VS Code ไปหา Ollama ใน Docker ผ่าน `localhost:11434` ใช้ [ตัวอย่าง config โหมด Chat](continue-config.example.yaml) โดยสำรองค่าที่มีอยู่ก่อนนำไปใช้ ไฟล์ตัวอย่างไม่มีผลกับ Continue อัตโนมัติ

ภาพเดิมแสดง Llama ตอบ “The answer is 20.” และ Qwen แสดงคำตอบ 20 ในกรอบโค้ดพร้อมข้อความส่วนเกิน ไม่มีเวลาที่วัดจาก Continue และยังไม่มีหลักฐานการเรียกเครื่องมือผ่าน Continue Agent UI ดู [คำอธิบายภาพ](screenshots/README.md)

MCP เป็นช่องทางให้ client เรียกเครื่องมือไฟล์จาก `mcp_server.py` มี [ผลตรวจการเชื่อมต่อ เขียน–อ่านไฟล์ และป้องกันการออกนอกพื้นที่งาน](evidence/mcp-probe.json) แยกจาก Agent หลักที่เรียกเครื่องมือ Python โดยตรง มี [ตัวอย่าง config MCP](continue-mcp.example.yaml) ซึ่งต้องเปลี่ยนพาธให้ตรงกับโปรเจกต์จริงก่อนใช้

## ข้อจำกัดและการพัฒนาต่อ

- คำถามและรอบซ้ำยังน้อย โมเดลมีขนาดและความยาวคำตอบต่างกัน เวลารอจึงไม่ใช้แทนคุณภาพหรือความเร็วสร้างโทเคนล้วน
- ลำดับการเรียกคงที่ Qwen ก่อน Llama และสภาพการโหลดโมเดลก่อนเริ่มอาจต่างกัน
- Agent ทำงานกับไฟล์ข้อความในพื้นที่งานแยกแต่ละรอบ รองรับสูงสุด 32 KiB ต่อไฟล์ พร้อมป้องกันการออกนอกพื้นที่งาน
- ยังไม่มีผลยืนยัน Continue Agent UI การสร้างเว็บจาก `prompt.txt` หรือการทดสอบข้ามเครื่องผ่าน Wi-Fi ในชุดนี้
- งานพัฒนาต่อ: ทดลองซ้ำหลายรอบต่อโจทย์ แยกสภาพที่โมเดลโหลดอยู่กับที่ต้องโหลด และเพิ่มโจทย์ Agent ที่ใช้ประโยชน์ได้มากขึ้น

## แก้ปัญหาเบื้องต้น

| อาการ | สิ่งที่ตรวจ |
|---|---|
| ติดต่อ Ollama ไม่ได้ | เปิด Docker Desktop แล้วใช้ `docker compose up -d ollama` และตรวจ `docker compose ps` |
| ไม่พบโมเดล | ตรวจ `docker compose exec ollama ollama list` แล้วดาวน์โหลดตัวที่ขาดขณะมีอินเทอร์เน็ต |
| ชื่อหรือพอร์ตซ้ำ | ตรวจ container เดิมและขั้นตอนย้ายระบบด้านล่าง |
| แก้โค้ดแล้วโปรแกรมยังเหมือนเดิม | build image ของ compare และ agent ใหม่ก่อนเปิดรอบถัดไป |
| Agent ได้ incomplete | อ่านบันทึกของรอบนั้นและเปิดไฟล์จริงเพื่อตรวจขั้นที่ไม่ผ่าน |

### ย้ายจากคอนเทนเนอร์เดิมครั้งเดียว

ใช้เฉพาะกรณีเคยสร้าง `ollama` ด้วย `docker run` ตรวจพื้นที่เก็บเดิม:

```bash
docker inspect ollama --format '{{range .Mounts}}{{println .Type .Name .Destination}}{{end}}'
```

ต้องพบ `volume ollama /root/.ollama` หากไม่ตรง ให้ปรับการอ้างอิง volume ก่อน เมื่อไม่มีคำขอ AI กำลังทำงาน ให้รันทีละคำสั่งและหยุดหากมี error:

```bash
docker stop ollama
docker rename ollama ollama-backup
docker compose up -d ollama
docker compose ps
docker compose exec ollama ollama list
```

`ollama-backup` เป็น container เดิมที่หยุดไว้ ใช้ volume เดียวกัน ไม่ใช่สำเนาโมเดลแยกชุด อย่าเปิดพร้อมตัวใหม่ หากต้องย้อนกลับ ให้รันทีละคำสั่ง:

```bash
docker compose down
docker rename ollama-backup ollama
docker start ollama
```

### ผลตรวจโค้ดและรายละเอียด Agent

มีโค้ด unit tests ปัจจุบัน 27 ข้อ รวมกรณีข้อความผิดรูปที่เคยทำให้ compare ล้ม ส่วน [บันทึกผลทดสอบที่แนบ](evidence/unit-tests.txt) เป็นรอบเดิม 21 ข้อก่อนเพิ่มกรณีดังกล่าว การตรวจโค้ดแยกจากการรันโมเดลจริง

Agent ใช้ JSON เป็นค่าเริ่มต้น ส่วน `--protocol native` เป็นรูปแบบ tool calling อีกแบบที่ใช้กับโมเดลใน Docker ได้ คำว่า `--runtime docker` เป็นป้ายบริบทในบันทึก ขณะที่ Docker Compose เป็นผู้รันโปรแกรมใน container

เครื่องมือตรวจซ้ำอยู่ใน `scripts/inspect_runtime.py`, `scripts/verify_docker.py` และ `scripts/probe_mcp.py` ดูรายละเอียดใน [เอกสารสถาปัตยกรรม](docs/ARCHITECTURE.md)
