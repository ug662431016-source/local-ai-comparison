# สารบัญผลเปรียบเทียบเดิม

ผลนี้ได้จาก `chat_input.py` เรียก Qwen2.5-Coder 1.5B และ Llama 3.2 3B ผ่าน Ollama ไฟล์ JSON เก็บ prompt, system prompt, options, คำตอบและเวลา ส่วน TXT เป็นฉบับอ่านง่ายของรอบเดียวกัน ไม่ใช่การทดลองเพิ่มอีกหนึ่งรอบ

## จำนวนและความสมบูรณ์

- JSON ที่อ่านได้ 12 ไฟล์ = 12 รอบ × 2 โมเดล = 24 คำตอบ
- คำถามไม่ซ้ำ 8 ข้อความ ดูข้อความเต็มใน [prompts.md](../prompts.md)
- JSON ว่าง 1 ไฟล์: `20261019_094041_455894.json` ขนาด 0 ไบต์ ไม่มี TXT คู่กัน ไม่นับเป็นผลสำเร็จและคงไว้โดยไม่แก้ข้อมูลเดิม
- Qwen มี `truncated=true`, `done_reason=length` 2 คำตอบในโจทย์ท่องเที่ยว ส่วนอีก 22 คำตอบมี `done_reason=stop`

## การตีความ

1. 4 รอบวันที่ 18 ตุลาคมเป็นชุดเปรียบเทียบแรก ส่วนวันที่ 19 ตุลาคมมีทั้งโจทย์ใหม่และโจทย์ซ้ำ ต้องอ้างอิง run ID เมื่อเปรียบเทียบ
2. รอบซ้ำไม่ได้มีสภาพเริ่มต้นเหมือนกันทั้งหมด เช่น `load_seconds` บางรอบใกล้ศูนย์ จึงยังใช้เป็นผลสถิติแบบควบคุมปัจจัยไม่ได้
3. คำตอบ `stop` อาจผิดเนื้อหาหรือทำตามโจทย์ไม่ครบ ส่วน `length` หมายถึงคำตอบถึงขีดจำกัดโทเคน ต้องแยกสองประเด็นนี้
4. โจทย์ image/container มีคำอธิบายผิดและข้อความซ้ำในทั้งสองโมเดล ดูการประเมินใน [README](../README.md#ผลเปรียบเทียบเดิม)
5. โจทย์ท่องเที่ยวของ Qwen พูดซ้ำจนถูกตัดทั้งสองรอบ ส่วนข้อมูลสถานที่ของ Llama ยังต้องตรวจแหล่งข้อมูลจริงก่อนใช้งาน
6. ผลเดิมไม่มีช่อง endpoint/runtime จึงไม่ใช้ JSON เหล่านี้เป็นหลักฐานติดตั้งโมเดล native แทนหลักฐานโปรเซสและรายชื่อโมเดล

## แยกจากผลใหม่

ผล Agent บันทึกใน `../agent_results/` และไฟล์งานใน `../agent_workspace/` ไม่รวมในการนับ 12 รอบ/24 คำตอบนี้ Qwen+JSON มีผลผ่านและมีผลอีกหลายรอบไม่ครบตามที่แจกแจงใน [README](../README.md#ผลตรวจ-agent-ใหม่) ส่วน `../evidence/environment-docker.json` เป็นรอบตรวจ metadata และ 10+10 ใหม่ ไม่รวมกับ 12 รอบเดิม หากเพิ่มผลถาม–ตอบในโฟลเดอร์นี้ภายหลัง ให้ปรับจำนวนและสารบัญตามไฟล์ที่เพิ่มจริง

ไม่มีการแก้คำตอบ เวลา หรือ JSON/TXT เดิมเพื่อให้ผลดูดีขึ้น
